# Журнал изменений

## [Не выпущено]

Исходный код закрыт от просмотра: репозиторий только по приглашению. Образ в Docker Hub остаётся открытым.

### Изменено

- Новая лицензия: закрытое ПО, пользоваться можно только с разрешения владельца, исходный код конфиденциален,
  восстанавливать его из образа запрещено. Выпущенные раньше версии остаются под прежней лицензией.
- Из релиза убрана подпись архивов GitHub: в закрытом репозитории она недоступна без Enterprise.
- В данные сборки образа больше не попадает Dockerfile (`--provenance=mode=min`).
- Описание на Docker Hub больше не ссылается на закрытый репозиторий.

## [1.0.9] — 2026-11-02

Исправлено то, что нашлось при проверке 1.0.8 на настоящем Kerio Connect 10.0.6.

### Исправлено

- Опрос Key Manager Plus и проверка серверов могли идти вдвое реже настройки: при интервале 15 минут — раз в 30. На
  тестовом стенде это повторялось каждый раз. Теперь ожидание до срока всегда заканчивается опросом; после прохода очереди
  срок прежний, а не интервал заново.
- Порт из списка проверки не отвечает по TLS, а остальные уже подают новый сертификат имени: это установка с замечанием,
  а не отказ. Раньше письмо говорило «🔴 не установлен» и советовало перезапустить службу, хотя сертификат подавался и
  перезапуск не помог бы. Теперь — «🟠 установлен» с номерами портов, и в сводке очереди тоже. Если не ответил ни один порт
  — отказ без этого совета; если порт подаёт другой сертификат — совет остаётся. Установка сертификата по умолчанию
  по-прежнему откатывается, пока не подтвердятся все порты.
- В письмах порт, который не отвечает, теперь назван одной фразой на всех языках: на английском и украинском часть
  строки оставалась по-русски.
- Вкладка «Сертификаты»: метка сервера стоит только у выпуска, который лежит в хранилище этого сервера, а не у всех
  выпусков того же имени. Для этого в хранилище обзора появилось поле `kmp_serial`.

## [1.0.8] — 2026-11-02

Проверка всего сервиса: логика установки и писем, повторы, отказы, дублирование кода в сервисе и панели.

### Исправлено: установка

- Чужой доверенный сертификат, который действует дольше выпуска KMP, не заменяется и позже первой привязки. В состоянии
  такой сертификат — «В порядке», а не ошибка и не отставание.
- Защита от отката работает и для сертификатов имён: старую пару, которую KMP показал заново, сам сервис не поставит,
  только по кнопке.
- При выключенном Key Manager Plus ничего не ставится, даже из старого снимка; кнопка «Обновить» сразу отвечает отказом,
  а не принимает нажатие, которое затем молча пропадает.
- KMP ответил пустым списком при известных сертификатах — это сбой опроса: снимок сохраняется, а не считается, что все
  сертификаты пропали.
- Нажатия «Обновить» гаснут при отключении сервера и при смене его адреса; после смены адреса забывается и прежнее
  состояние установок.
- «Обновить» при пароле, который Kerio уже отверг, сразу отказывает: лишний вход приближал блокировку учётной записи.
- Пауза перед повтором после неудачи растёт дольше: 5, 15, 30 минут, 1, 3, 6, 12 часов, затем раз в сутки.
- Занятый слот установки больше не держит сервер бесконечно: через 90 секунд имя остаётся в очереди до следующего прохода.
- Промежуточный проход очереди трогает только серверы, где есть что ставить; аренда сервера продлевается, пока идёт работа.
- Остановка контейнера: службы останавливаются разом, срок `stop_grace_period` — 2 минуты 30 секунд, чтобы откат
  прерванной установки успевал закончиться.

### Исправлено: письма

- Несколько условий на сервере за один проход приходят одним письмом с таблицей (`alerts_digest`), а не отдельными.
- Сводка очереди уходит, только если что-то встало; при неудачной отправке она не теряется.
- Письмо о сроке не уходит про сертификат, который только что встал, и ждёт, пока он стоит в очереди. Память об уже
  ушедших письмах не стирается проходом, не дошедшим до сервера.
- Получатели — общий список вместе с адресами сервера. Сохранение адресов не ждёт прохода синхронизации: раньше сохранение
  нескольких серверов могло оборваться на занятом сервере.
- Составные тексты писем и ошибок переводятся целиком; имя в кавычках — данные, сервер «Журнал» не становится «Log».

### Исправлено: панель

- Обзор: «Обновить» заранее объясняет отказ (сервер отключён, нет пароля, пароль отвергнут, нет прав); фильтры считают
  только включённые серверы; под фильтром найденное раскрыто всегда; пока хранилище не прочитано, выбранные сертификаты
  видны со статусом «Хранилище не прочитано»; то, что подано по TLS, не считается «не из KMP».
- На телефоне строка сертификата показывает те же сведения, что на ПК: предупреждение о цепочке, другие имена, значки
  «по умолчанию» и KMP.
- Неудачный опрос больше не стирает страницу: видны последние данные и причина.
- Журнал установок обновляется сам, пока установка идёт. Ошибка догрузки «Показать ещё» не стирает список, а устаревший
  ответ при смене фильтра отбрасывается.
- Окна закрываются при выходе из сеанса и при смене адреса кнопками браузера.
- Мастер подключения показывает ошибку списка KMP вместо пустого списка; «стоит на сервере сейчас» — про сертификат
  по умолчанию, а не про первую подсказку.
- Настройки сервера: повторная проверка доверия видит только что подтверждённый отпечаток; при несохранённом новом адресе
  она недоступна. Текущий выпуск имени выбирается так же, как на сервере.
- Пробное письмо из настроек — на языке панели. Цвет срока не бывает красным раньше порога предупреждения.
- Подписи, множественное число, доступность: переключатели и окна подписаны для программ чтения с экрана.

### Изменено

- API: убраны `PUT /kerio/servers/{id}/password`, `clear_common_name` (пустой `common_name` снимает сертификат по
  умолчанию), `server_id` у `/kerio/servers/test`. Проверка и опрос KMP — под пределом частоты.
- Интервал прохода задаётся в одном месте — на вкладке «Синхронизация». Исход «Ошибка» в журнале
  теперь «Не установлен», «Тестовое письмо» — «Пробное письмо».
- Убрано дублирование: одна модель строки обзора для ПК и телефона, один постраничный список, общие баннер и переключатель,
  один `BoundSecret`, правила автоустановки и текущего выпуска в одном месте. Удалён неиспользуемый код.
- Миграция `ServerCounters`: столбцы `default_selected_at`, `tls_failures` в `kerio_servers`.

### Безопасность и развёртывание

- Роль сервиса больше не получает прав по умолчанию на новые таблицы: новая партиция журнала была бы ей доступна на
  правку до следующего `migrate`. Права на таблицы новых миграций выдаёт `migrate`.
- `/api/ready` решает по базе: нехватка партиций журнала — ошибка в логе, панель из-за неё не падает.
- Опечатка в команде контейнера — код 2 и список команд, а не второй запущенный сервер.
- Демо-ключ не примет ни другая версия, ни соседняя строка файла. HSTS не отдаётся для `localhost`. Ответ `/api/ready`
  и ошибки переводятся как прочие. База новее кода — предупреждение в логе.
- Выпуск проверяет совпадение версии тега с файлами и разделом журнала изменений. `latest` двигается только на самую новую
  версию, `X.Y` — на самую новую в своей ветке.

## [1.0.7] — 2026-11-02

### Исправлено

- **«Истекли» считали старые версии.** Когда для имени в хранилище Kerio уже стоит новый сертификат, прежние
  истёкшие версии этого имени попадали в плитки «Истекли» / «Не из KMP» и в счётчики на карточке сервера. Теперь
  в «Обзоре» одна строка на имя — самая новая версия; старые, которые Kerio уже не подаёт, не показываются и не
  считаются. Если Kerio всё ещё подаёт старую версию, видны обе строки — это настоящая проблема. В API у сертификата
  хранилища — признак `superseded`.
- У сертификата, который нажали «Обновить» и он в очереди, состояние было «ждёт ручной установки» — теперь
  «в очереди на установку».

### Изменено

- Метка «подаётся для …» — только когда Kerio подаёт сертификат для другого имени (например, `*.домен`); для своего
  имени она ничего не добавляла. Синим выделен только сертификат по умолчанию.

## [1.0.6] — 2026-11-02

### Изменено

- **Об установках из очереди — одно сводное письмо.** Когда у сервера в очереди больше одного сертификата, удачные
  установки не пишутся по одной: когда очередь опустела, уходит одно письмо — сколько установлено, сколько не удалось,

  Сводку включает и выключает тот же выключатель «Сертификат установлен» (`kerio.alert_deployed`); в истории
  оповещений — событие `queue_summary`, письмо вида `kerio_queue_summary`.
- Миграция `QueueReport`: столбец `queue_report_since` в `kerio_servers`.

## [1.0.5] — 2026-11-01

### Изменено

- **Нет лимита на число сертификатов у сервера** (было 20 сертификатов имён).
- **Очередь установки.** Во всём сервисе сертификаты ставятся по одному: проверки серверов идут параллельно, а
  ставит только держатель общего слота. Сервер ставит один сертификат за проход; пока очередь не пуста, следующий
  проход начинается, как только Kerio перезапустил HTTPS (около 45 с), без нового опроса Key Manager Plus. Порядок:
  нажатые «Обновить» / «Добавить» — по времени нажатия, затем истёкшие, недостающие и истекающие раньше.
- **Нажатия копятся**: каждое «Обновить» / «Добавить» — запрос в очереди, повторное нажатие не дублирует, а правка
  сервера во время прохода нажатие не теряет. В API у сервера вместо `deploy_requested_at` / `deploy_requested_name` —
  `install_queue` (порядок) и `installing` (что ставится сейчас).
- **Панель**: у сертификата в очереди — «В очереди · №N», у того, что ставится, — «Ставится»; на карточке сервера —
  длина очереди; сверху — баннер «Сертификаты ставятся по одному» с тем, что ставится сейчас.
- **Карточка сервера в «Обзоре» — один список сертификатов.** Отдельного блока «Из Key Manager Plus» больше нет:
  сертификат по умолчанию — сверху и выделен (метка «по умолчанию»), затем недостающие выбранные, затем остальное
  хранилище. Причина, почему выбранный сертификат не в порядке, — под его состоянием.
- Миграция `InstallQueue`: таблицы `kerio_install_requests` и `kerio_install_slot`, столбец `install_queue`; ждущий
  ручной запрос переносится в очередь, столбцы `deploy_requested_*` удаляются.

### Исправлено

- **Хранилище Kerio больше 100 сертификатов читалось не целиком**, а поиск своего сертификата при установке
  смотрел только первые 64. При десятках имён с прежними версиями сервис мог не увидеть сертификат и ставить
  его заново. Теперь хранилище читается целиком.

## [1.0.4] — 2026-11-01

### Изменено

- **«Обновить» — только у сертификатов, выбранных для сервера** (по умолчанию и сертификаты имён). У чужих и
  положенных вручную кнопки больше нет, и API не ставит их: `POST /api/kerio/servers/{id}/deploy` с невыбранным
  `common_name` отвечает `400`. Чтобы сервис вёл такое имя — выберите его в настройках сервера.
- **«Добавить» — для выбранного сертификата, которого нет на сервере**: он первой строкой в списке сервера во вкладке
  «Обзор», состояние «Нет на сервере».

### Исправлено

- **Выбранный для сервера сертификат не вставал**, пока у сервера выключено «Ставить продлённые автоматически», —
  висел «Ждёт установки». Выключатель сервера теперь держит только продления; первая установка только что выбранного
  сертификата идёт сразу. Общая пауза автоустановки по-прежнему держит всё.
- **Подпись «установка в ближайшем проходе»** при общей паузе: теперь «ждёт ручной установки». Баннер паузы называет
  обе кнопки — «Обновить» и «Добавить».

## [1.0.0] — 2026-10-31

Первый выпуск Kerio Cert Manager: SSL-сертификаты из ManageEngine Key Manager Plus — на серверы Kerio Connect.

### Добавлено

- **Безопасность (ревизия перед публикацией).** Перевод ответов больше не нагружает процессор: шаблоны
  сверяются линейно, длинные строки не переводятся, на ответ — бюджет времени; выгрузки идут насквозь, без
  буфера в памяти. Адреса Kerio на loopback и link-local отвергаются; имя TLS в пробе проверяется. Правка
  сервера блокирует строку — проход её не перезапишет. Сертификат имени доверен на порту администрирования,
  только если покрывает его имя. Закрытый ключ разбирается в стираемом буфере; для сверки «свой ли» ключ из
  KMP больше не скачивается. Настройки оповещений — со свежим кодом. Первый администратор подключает
  аутентификатор в течение часа. HTTP через прокси — на HTTPS; у ответов API — строгий CSP. Ключ демо-стенда
  в бою не принимается.
- **Развёртывание.** Образ — открытый, в Docker Hub: `danreero/kerio_cert_manager`. Базовые образы,
  cloudflared и postgres закреплены по хешу; `npm ci --ignore-scripts`; в образе нет XML-документации и
  символов отладки. Стек Portainer передаёт секреты файлами (`secrets: environment`), а не переменными
  контейнеров. Демо-стенд — без туннеля, со своими портами (`KCM_DEMO_PORT`), эмулятор — не от root.
- **Выпуск.** CI на каждый push (сборка, тесты, аудит зависимостей); релиз — только после CI, с проверкой
  образа Trivy, SBOM и подписанным происхождением; Dependabot.
- **Быстрее.** Одинаковые ответы переводятся один раз; список серверов без хранилища Kerio (оно — только в
  обзоре), выпуски KMP по серийному — один раз на запрос; рукопожатия по именам — параллельно; индексы для
  журнала установок и снимка KMP; панель не опрашивает скрытую вкладку и не копит запросы, разделы грузятся
  по требованию (стартовая часть — 44 КБ вместо 144).
- **Документация.** README на английском и русском, подробное руководство пользователя на обоих языках со
  скриншотами, описание для Docker Hub, политика безопасности на двух языках. Комментарии в коде сокращены.

- **Kerio Cert Manager** — новое имя сервиса (прежнее рабочее — CertBridge): проекты `KerioCertManager.*`,
  образ `kerio-cert-manager`, проект Compose `kerio-cert-manager`, база и роли `kcm`/`kcm_app`, переменные
  `KCM_*`, файлы секретов `secrets/kcm_*`. Установка под прежним именем ставится заново (данные прежней — в её
  томе, их можно удалить).
- **Язык интерфейса** — русский, английский, украинский: выбор в профиле, личная настройка `ui.locale` на
  сервере (умолчание установки — `ru`, `Settings:ui.locale`). Панель переведена целиком; тексты сервера —
  ошибки API, шаги журнала установок (и прежние), пояснения состояний — переводятся на выходе по словарю
  шаблонов (`Localization/en.json`, `uk.json` модуля Kerio) на язык из `Accept-Language`. Письма-оповещения —
  на языке `kerio.alert_locale`. Сборка панели падает, если у строки нет перевода (`npm run check:i18n`).

- **Серверы Kerio Connect** — сколько угодно: адрес администрирования, отдельная учётная запись,
  доверие TLS (закреплённый отпечаток или УЦ с именем), привязка к сертификату KMP, порты проверки,
  свои получатели писем, автоустановка, уборка старых версий.
- **Мастер подключения**: проба TLS до отправки пароля, проверка входа и роли, подсказка сертификата KMP по
  тому, что стоит на сервере, автопоиск портов служб с тем же сертификатом.
- **Цикл синхронизации**: опрос KMP, проверка каждого сервера по TLS и API, решение, установка;
  «Синхронизировать сейчас».
- **Установка** через API администрирования Kerio 10.0.6 (`ConnectCertificate`): проверка пары до
  обращения к Kerio, цепочка из PEM или P7B, ключ любого вида KMP (включая устаревший PEM OpenSSL),
  активация, **проверка рукопожатием на всех портах**, **откат** на прежний с подтверждением.
- **Защиты**: от отката на более старый выпуск, от спора с ручной правкой, от блокировки учётной записи
  Kerio перебором отвергнутого пароля, от признания поддельного сертификата по серийному номеру.
- **Надёжность установки**: откат и при остановке сервиса после активации (хост ждёт до двух минут),
  откат не зависит от записи журнала, без пути назад сервис сам не ставит, брошенные записи «идёт»
  закрываются, ставится ровно запрошенный серийный номер, порты STARTTLS в проверке отвергаются.
- **Пределы частоты** для пробы, теста входа и «Проверить»; тест не входит с уже отвергнутым паролем.
- **Только установка на Kerio**: скачивание файлов сертификатов и показ закрытого ключа убраны из API и
  панели — пара из KMP живёт в памяти одну установку. Вкладка «Сертификаты» — просмотр: что в KMP и на
  какие серверы уходит (по умолчанию или по имени).
- **Быстрее**: журнал установок — один запрос на страницу вместо запроса на каждую запись; сводка «Обзора» без
  лишнего запроса к базе; проход синхронизации обрабатывает до 4 серверов параллельно — зависший Kerio не
  задерживает остальные; из панели убраны неиспользуемые стили и код.
- **Проверено на живом Kerio 10.0.6** (тестовый сервер): выбор сертификата по SNI (из версий имени — та, что
  истекает позже), импорт не меняет сертификат по умолчанию, метка `ServerCertificate` — это он, удалить его
  нельзя. Через ~25 с после импорта или удаления Kerio перезапускает HTTPS и обрывает все сессии API —
  сессия теперь входит заново сама, иначе откат после долгой проверки не дошёл бы до Kerio; истёкшая сессия
  больше не считается отказом пароля. Уборка старых версий и подсказка имени при подключении — по
  настоящим меткам Kerio. Эмулятор воспроизводит всё это, включая обрыв сессий.
- **Несколько сертификатов на сервере**: список сертификатов KMP, один — по умолчанию, остальные — по именам
  (SNI, Kerio 9.0.2+). Сертификат имени кладётся в хранилище, сертификат по умолчанию возвращается и
  проверяется без SNI, прежняя версия имени убирается, новая проверяется с именем в SNI. Каждый проход
  проверяет по SNI, что для каждого имени подаётся свежий выпуск. Имени нет в KMP — не сохраняется: причина
  и подсказка написания.
- **Независимое ревью установки** (исправлено и покрыто тестами):
  - сертификат по умолчанию проверяется рукопожатием **без SNI** — по имени адреса Kerio подаёт сертификат этого
    имени, и проверка видела бы не тот;
  - откат сертификата по умолчанию убирает не вставший новый: он истекает позже, и клиенты по имени получали бы
    его и после отката;
  - сертификат имени: свои прежние версии узнаются по памяти сервиса, даже если KMP при продлении заменил запись;
    мешающие свои версии убираются, чужие — никогда (отказ с названием сертификата); доверенный чужой
    сертификат имени, что действует дольше выпуска KMP, автоматически не заменяется — как и по умолчанию;
  - аренда сервера продлевается перед каждой установкой, а вторая установка на тот же сервер в одном проходе ждёт
    перезапуска HTTPS (~40 с); правка сервера посреди прохода — `409`, а не тихая потеря при его сохранении;
  - первый вход переживает перезапуск HTTPS (до 15 с), повторный посреди установки — до минуты;
  - удача сертификата по умолчанию не снимает отметки отказов сертификатов имён; «повтор 0 ч» — одно письмо
    об отказе на выпуск, а не на каждую попытку;
  - доверие порта администрирования включает сертификаты имён, поставленные сервисом.
- **Пробный режим**, общий и посерверный выключатели автоустановки, «Установить сейчас».
- **Журнал установок** с пошаговыми записями; события в журнале действий.
- **Письма**: установлено, не установлено/откачено, предупреждения (истекает, истёк, нет в KMP, ждёт
  установки, сменили вручную, недоступен, пароль отвергнут, нет прав, недоверенный сертификат) без
  повторов чаще заданного.
- **Панель**: раскладка по режиму браузера (мобильный/десктопный), функции не дублируются между вкладками.
  - **Обзор** — только просмотр: карточки серверов свёрнуты, в заголовке — сводка; внутри — сертификаты
    KMP сервера с состоянием и всё хранилище Kerio (только чтением): что подаётся по умолчанию и по каким
    именам, из KMP, положенные вручную, встроенный; срок и состояние каждого. Плитки сверху — единственный
    фильтр «в порядке, истекают, истекли, не из KMP».
  - **Серверы** — управление: связь, «Синхронизировать», «Подключить сервер», «Проверить», карандаш
    (список сертификатов KMP с отметкой «по умолчанию», проверка имён по KMP до сохранения, автоустановка,
    порты, «Установить сейчас»; подключение и доверие TLS), удаление с кодом второго фактора на каждое
    удаление.
  - **Оповещения** — выключатель каждого события, первое предупреждение и напоминания (7, 3, 1 дн.),
    «не обновился сам за N ч», «недоступен с N проверок», повтор (0 — не повторять), общие и посерверные
    получатели, пробное письмо, журнал отправленных писем.
  - Журнал установок, сертификаты KMP, настройки установки, пользователи, журнал действий.
- **Порт панели** в `docker-compose.yml` настраивается: `KCM_HTTP_PORT` (по умолчанию `127.0.0.1:8001`,
  как в стеке Portainer), если порт на сервере занят; туннель ходит на `api:8001` и этого не замечает.
- **Исправлено**: `create-superadmin` и `reset-access` (`docker compose run api …`) при работающем API падали с
  «Address already in use» — у API был закреплённый адрес в сети туннеля. Теперь закреплён только адрес
  cloudflared, и он вне диапазона, откуда Docker раздаёт адреса (`KCM_TUNNEL_RANGE`);
  `KCM_TUNNEL_API_IP` больше не нужен.
- **Исправлено**: уборка старых версий сертификата по умолчанию убирала все сертификаты того же имени —
  и купленные или положенные вручную (например, Let's Encrypt, ключа от которого больше нигде нет). Теперь,
  как у сертификатов имён, — только свои: из KMP или поставленные сервисом; сервис помнит до 10 прежних своих
  выпуска (`previous_serials`, миграция `InstalledHistory`). Подсказки уборки в панели — точнее: переключатель
  действует на все сертификаты сервера, а своя версия имени, что действует дольше новой, убирается всегда.
- **Демо-стенд** `docker-compose.demo.yml`: сервис из Docker Hub, эмулятор KMP и двух Kerio Connect по HTTPS
  со своим УЦ и списками отзыва, Mailpit; только на этом компьютере.
- Модули EAMS копией в `modules/` на закреплённых версиях: core, crypto, hosting, identity, tokens, settings, mail,
  audit — весь код для сборки в репозитории, без доступа к другим.
