# Kerio Cert Manager

Сервис: сертификат продлили в ManageEngine Key Manager Plus (KMP) — через минуты он стоит на каждом Kerio Connect,
проверен по TLS на всех портах, при сбое откачен, а администраторы получили письмо. Веб-панель на трёх языках,
вход с паролем и TOTP. Работает в Docker, ставится через Portainer или Compose.

Перед работой прочитайте:

- [docs/CONTEXT.md](docs/CONTEXT.md) — текущее состояние, открытые задачи, ограничения, нюансы окружения;
- [docs/REFERENCE.md](docs/REFERENCE.md) — устройство, настройки, API, данные, безопасность;
- [docs/KERIO-API.md](docs/KERIO-API.md), [docs/KEYMANAGER-API.md](docs/KEYMANAGER-API.md) — проверенное поведение внешних API;
- [CHANGELOG.md](CHANGELOG.md) — что и зачем менялось в каждой версии.

## Правила владельца

Обязательны, пока владелец сам их не отменит.

- **Общение и тексты — по-русски.** Журнал изменений, коммиты и справочник — на русском; README и руководство — на
  английском и русском; панель и письма — ещё и на украинском.
- **Никаких упоминаний ИИ** в коде, документах, коммитах и PR, строк `Co-Authored-By` тоже нет. Это правило сильнее
  стандартных настроек инструмента. Исключение — имя этого файла.
- **Никаких секретов** в git: паролей, токенов, ключей, внутренних адресов, настоящих доменов и данных компании. Перед
  каждым push проверяйте изменённые файлы: значения из `secrets/`, шаблоны токенов и ключей, адреса локальной сети.
- **Пароли вводит только владелец** — пароль Kerio, администратора, токены. Не ищите их в старых томах и транскриптах.
- **Токенов в CI нет.** Модули лежат в репозитории, образ публикует владелец своим `docker login`.
- **Комментарии короткие:** однострочный `/// <summary>`, заметка `// ⚠` там, где легко ошибиться. Объяснения — в `docs/`.
- **Без дублей** на бэкенде и во фронтенде. У действия одна точка входа: новое кладите на вкладку, чьей роли оно
  соответствует.
- **Что считается сделанным:** тесты, сборка панели, проверка на стенде. О том, что не проверено, — говорить прямо.
- Безвозвратно ничего не удалять (файлы — в корзину). Адреса получателей не писать в журнал действий.
- Вкладка «Журнал» — владелец назвал её сделанной идеально: внешний вид не менять.

## Архитектура

Модульный монолит: хост, два модуля предметной области и копии общих модулей.

| Проект | Роль |
|---|---|
| `KerioCertManager.Api` | Хост: конвейер, права, команды консоли, миграции, отдача панели |
| `KerioCertManager.Modules.KeyManager` | Источник: опрос KMP, снимок, ключ API, выгрузка пары и цепочки; контракт `ICertificateSource` |
| `KerioCertManager.Modules.Kerio` | Серверы, клиент JSON-RPC, решения, установка с откатом, цикл синхронизации, письма |
| `KerioCertManager.Web` | Панель |
| `KerioCertManager.Emulators` | Стенд: эмулятор KMP и Kerio 10.0.6, в образ сервиса не входит |
| `modules/*` | Копии модулей `core`, `crypto`, `hosting`, `identity`, `tokens`, `settings`, `mail`, `audit`; версии — в `modules/README.md` |
| `*.Tests`, `KerioCertManager.IntegrationTests` | Модульные тесты и хост целиком на настоящем PostgreSQL |

Модуль Kerio знает модуль KeyManager только через `ICertificateSource`.

Один проход на сервер, файлы в `KerioCertManager.Modules.Kerio/Sync/`:

```
ServerInspection (TLS + API) → DeployPlanner (по умолчанию) и ExtraPlanner (имена)
  → InstallQueue → KerioDeployer (проверка, импорт, сверка портов, откат) → SyncCycle: письма и журнал
```

`SyncWorker` задаёт ритм. `SyncCycle` — проход. Проверки серверов идут параллельно (до 4), ставит только держатель
слота `kerio_install_slot`.

Сертификаты сервера — это **список**:

- `CommonName` — сертификат по умолчанию: подаётся без SNI, меняется через `setActive`, откатывается;
- `Extras` — сертификаты имён: Kerio подаёт их по SNI, проверка идёт по SNI, отката нет.

Роли вкладок панели: **Обзор** — состояние, из действий только «Обновить» и «Добавить» в строке сертификата;
**Серверы** — управление; **Оповещения** — правила писем; **Журнал** — установки; **Настройки** — только настройки.

## Команды

```bash
# Всё решение. Нужен Docker.
dotnet build KerioCertManager.slnx
dotnet test --solution KerioCertManager.slnx

# Панель. Именно build: tsc, проверка переводов, vite.
cd KerioCertManager.Web && npm ci && npm run build
cd KerioCertManager.Web && npm run dev              # :5173, прокси /api на :8001
cd KerioCertManager.Web && node scripts/check-i18n.mjs --prune

# Зависимости для dotnet run: PostgreSQL и Mailpit.
docker compose -f docker-compose.dev.yml up -d

# Новая миграция модуля Kerio. Затем добавьте шапку РАЗРУШАЮЩИХ ОПЕРАЦИЙ / ОБРАТИМОСТЬ, как в соседних.
dotnet ef migrations add Имя --project KerioCertManager.Modules.Kerio --startup-project KerioCertManager.Api --context KerioSchema --output-dir Schema/Migrations

# Обновить копию модуля из его репозитория (код, module.json, таблица версий; сокращает комментарии).
dotnet run tools/copy-module/copy-module.cs -- ../module-core

# Документ API без сервера и базы.
./scripts/export-openapi.sh
```

Демо-стенд на своих портах, вход и порядок действий — в шапке `docker-compose.demo.yml` и в `docs/CONTEXT.md`:

```bash
docker buildx build --load -f KerioCertManager.Api/Dockerfile --build-arg VERSION=X.Y.Z -t kerio-cert-manager:demo .
KCM_DEMO_IMAGE=kerio-cert-manager:demo KCM_DEMO_PORT=18011 KCM_DEMO_EMULATOR_PORT=18081 KCM_DEMO_MAIL_PORT=18026 docker compose -f docker-compose.demo.yml up -d --no-build
# Разобрать с теми же переменными: docker compose -f docker-compose.demo.yml down -v
```

Установка из командной строки: `scripts/gen-secrets.sh`, `scripts/set-tunnel-token.sh`, `cp .env.example .env`, затем:

```bash
docker compose pull api
docker compose run --rm migrate     # профиль tools: API не стартует на отставшей схеме
docker compose up -d
```

В Portainer служба `migrate` запускается сама: новая версия в `KCM_IMAGE` → **Update the stack**.

Консольные команды образа: `migrate`, `create-superadmin`, `set-superadmin-password`, `reset-superadmin-2fa`,
`reset-access`, `rewrap-keys`, `verify-audit-chain`, `export-openapi`, `health`.

## Выпуск

1. Заменить версию: `Directory.Build.props`, `KerioCertManager.Web/package.json`, первые две записи
   `package-lock.json`, `docker-compose.yml`, `deploy/portainer/docker-compose.yml`, `docker-compose.demo.yml`,
   `.env.example`, `deploy/portainer/.env.example`, `README.md`, `README.ru.md`, `deploy/dockerhub/README.md`.
2. Раздел в `CHANGELOG.md`: `## [X.Y.Z] — дата`. Заголовок `## [Не выпущено]` на этот момент переименовать:
   `release.yml` проверяет версию в файлах и раздел журнала.
3. Тесты, `npm run build`, проверка на стенде. Перед выпуском — пробное развёртывание стека Portainer со случайными
   секретами в своём проекте и подсети.
4. Коммит и push в `main`, затем публикация образа (около 7 минут, нужен `docker login` владельца):

   ```bash
   ./scripts/publish-image.sh X.Y.Z
   ```

   Теги `X.Y.Z`, `X.Y` и `latest`; два последних двигаются только для самой новой версии.
5. Тег: `git tag -a vX.Y.Z -m "Kerio Cert Manager X.Y.Z"` и `git push origin vX.Y.Z`. Workflow `release` прогонит
   тесты, скачает опубликованный образ, проверит его Trivy и создаст страницу релиза с архивами.
6. Репозиторий закрыт, поэтому результат смотрите на вкладке **Actions** (`gh` на этой машине не было).

Обновить `deploy/dockerhub/README.md` на Docker Hub можно только вручную: **Repository overview → Edit**.

## Соглашения кода

- Внутренние имена — часто по-русски (`ПаузаОчереди`, `СледующийПроход`), публичные контракты, JSON и база — по-английски,
  JSON в `snake_case`. Пишите так же, как соседний код.
- `TreatWarningsAsErrors`, неиспользуемые `using` (IDE0005) — ошибка сборки.
- Время — через `TimeProvider`, а сроки сертификатов в днях — по календарю UTC.
- Исходный язык текстов — русский. Новый текст панели — через `t('…')` и `src/locales/{en,uk}.json`: без записи сборка
  падает. Новый текст сервера — запись в `KerioCertManager.Modules.Kerio/Localization/{en,uk}.json`; `ServerTexts`
  переводит на границе API по `Accept-Language`.
- CSP `script-src 'self'` и `style-src 'self'`: никаких встроенных скриптов и атрибутов `style=`, оформление — классами в
  `styles.css`; телефон или компьютер — через `html[data-device]`.
- `Modules.Core.InTransactionAsync` сначала очищает трекер EF: меняйте сущности внутри действия.
- Очередь писем требует транзакцию вызывающего и сама не вызывает `SaveChanges`.
- Репозиторий хранит LF (`.editorconfig`, `.gitattributes`), JSON-столбцы — с `ValueComparer`.
- Действия GitHub закреплены по хешу коммита, базовые образы — по digest, npm — `--ignore-scripts`.
- Заметки, которых не должно быть в git, — в `.local/`.

## Ключевые решения и почему

- **Источник правды — TLS-рукопожатие, а не метки API Kerio.** 30.10.2026 список Kerio показывал не то, что подавалось
  на самом деле; после этого любое решение и проверка идут по отпечатку с порта.
- **Сертификат признаётся только по SHA-256** выгрузки из KMP, серийного номера мало.
- **Текущий выпуск — замеченный позже всех, а не самый долгий:** перевыпуск бывает короче прежнего.
- **Пустой ответ KMP при известных сертификатах — сбой опроса,** снимок остаётся: иначе сбой выглядел бы как отзыв всего.
- **Чужой доверенный сертификат, действующий дольше выпуска KMP, не заменяется:** нельзя делать «хуже, чем было».
- **Ручная правка на сервере не оспаривается:** сервис пишет письмо, а не ставит обратно.
- **Откат — только у сертификата по умолчанию.** Новая версия имени при сбое проверки остаётся в хранилище, следующий
  проход её признаёт. Порт не ответил, а другие уже подают новый сертификат имени — это успех с замечанием (🟠).
- **Сертификат по умолчанию откатывается при любом непроверенном порте,** даже закрытом: этот путь не проверялся на
  настоящем Kerio, а откат безопаснее.
- **Одна установка во всём сервисе и один сертификат за проход:** через ~25 с после импорта Kerio перезапускает HTTPS и
  обрывает сессии API. Отсюда пауза 40 с на сервер и следующий проход очереди через 45 с. Лимита на число сертификатов нет.
- **Одно сводное письмо на очередь:** 30 писем об успехе — шум. Отказы пишутся сразу.
- **«Обновить» и «Добавить» — только для выбранных у сервера имён,** запрос на остальные — `400`. Новое выбранное имя
  ставится и при выключенной автоустановке сервера; общая пауза держит всё.
- **Одна строка на имя — самая новая версия.** Метка «подаётся для X» — только если X отличается от имени сертификата.
- **Модули — копии в `modules/`, а не submodule:** так CI не нужен токен к закрытым репозиториям модулей. Версия
  закреплена в `module.json`, модули развиваются отдельно.
- **GitHub закрыт, образ на Docker Hub открыт** (решение владельца 02.11.2026; повторно закрывать образ не предлагать).
  Поэтому в релизе нет подписи архивов (в закрытом репозитории нужен Enterprise), `publish-image.sh` использует
  `--provenance=mode=min` (иначе в открытый образ попадёт Dockerfile), а описание на Docker Hub не ссылается на GitHub.
- **Лицензия закрытая,** пользоваться — только с разрешения, восстанавливать код из образа запрещено; владелец подтвердил
  это и при открытом образе. Версии до 1.0.9 включительно остаются под прежней бесплатной лицензией.
- **Защита не зависит от секретности кода:** пароль с TOTP, свежий код перед опасными действиями, AES-256-GCM с
  мастер-ключом, журнал с цепочкой хешей. Перед панелью рекомендуется Cloudflare Access.
- **Обфускация не вводилась:** старые образы всё равно доступны, а риск сломать EF и сериализацию реальный.

## Что важно помнить о Kerio 10.0.6

Проверено опытами; подробности — в [docs/KERIO-API.md](docs/KERIO-API.md).

- Тип `ServerCertificate` в `ConnectCertificate.get` — сертификат по умолчанию; `ActiveCertificate` — любой другой действующий.
- `importCertificate` не меняет сертификат по умолчанию. По SNI подаётся действующая версия имени с самым поздним сроком.
- `setActive` переключает сразу и без перезапуска, на текущем сертификате по умолчанию ничего не делает.
- Удалить сертификат по умолчанию нельзя (ошибка `1003`). Сессия истекла — `-32001`; это не отказ в доступе.
- Одно хранилище на все службы. Учётная запись сервиса — FullAdmin без второго фактора.
