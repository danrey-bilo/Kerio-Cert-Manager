## Исходная задача

30.10.2026 владелец попросил связать ManageEngine Key Manager Plus 7.1.1 (центр сертификатов) и Kerio Connect 10.0.6
своей прослойкой: продлили сертификат в KMP — он сам обновился в Kerio. Условия: использовать готовые модули вместо
лишнего кода (вход, письма и так далее), сначала разобрать оба API и составить план. Шаблоном стал соседний проект
`danrey-bilo/eams-ssl-sender`. Сначала сервис назывался CertBridge, 31.10.2026 переименован в Kerio Cert Manager.

Как устроена сводка очереди (сессия «Одно сводное письмо после очереди установки»): проход, увидевший в очереди больше
одного сертификата, ставит `queue_report_since`, и удачи письмами не пишутся. Когда очередь пуста, уходит
`kerio_queue_summary` по журналу с этого времени. Повтор после сбоя в той же очереди показывается только как удача,
отказы идут первыми, пробные прогоны и незавершённые установки не входят. Письма об отказе уходят сразу, одиночные
установки пишут обычное письмо. Письмо приходит каждому получателю отдельно: две копии при двух получателях — это норма.

Установка без интернета: `docker save` образа на компьютере с доступом и импорт на сервере; архив образа есть и в релизе.

## Известные ограничения и баги

Подтверждённых открытых ошибок в коде нет. Что стоит знать:

- **Причина редких проходов до 1.0.9 не доказана отдельно.** Замер шёл на стенде под Docker Desktop: при интервале в минуту
  было +120 с, стало +60 с. Причина — сравнение часов на самой границе срока — совпадает с замером; новый код решает всё
  до ожидания. Поэтому журнал пишет «могли идти вдвое реже».
- **Сертификат по умолчанию при закрытом порте откатывается всегда.** Закрытый порт в списке проверки не даст его заменить.
- **`ServerTexts`:** шаблон, начинающийся с подстановки (например `{0}:{1} недоступен: {2}.`), поглощает предыдущие
  предложения, и склеенный текст не переводится. Поэтому письма используют простые цельные фразы. Порядок разбора:
  `ПоХвосту` (ключи с ведущим пробелом) → `ПоШаблону` → `ПослеМетки` → `ПоПредложениям`.
- **`GET /api/kerio/servers` отдаёт `store: []` без `?include=store`.** Это не баг: хранилище тяжёлое, обзор берёт его сам.
- **Правка сервера во время прохода — `409`** (`KERIO_SERVER_BUSY`). Скриптам нужен повтор, иначе правка не применится.
- **Сразу после установки порт может молчать:** Kerio перезапускает HTTPS. Пустой ответ в первые секунды — не ошибка.
- **Код можно восстановить из открытого образа:** в DLL остаются имена. Отладочных файлов и карт исходников в образе нет.
- **Файлы панели отдаются без входа,** в них видны адреса API. Это обычное свойство веб-приложения; скрывает Cloudflare Access.
- **В образах 1.0.0–1.0.9 в данных сборки лежит Dockerfile** с комментариями. Секретов в нём нет.

Сознательно не сделано — не «исправляйте», не прочитав причину:

| Что | Почему |
|---|---|
| Объединить `ServerPasswords.NormalizeUrl` и `ApiKeyStore.Target` | Запечатанные секреты привязаны к адресу и перестанут открываться |
| Заменить `MasterKeyFile.Read` | HMAC отметки сброса считается по сырому содержимому |
| Общий токен отмены на проверку и откат при остановке | Отмена пропустила бы откат |
| Повтор старта 60 с при сбое базы | Хватает политики перезапуска контейнера |
| `start_interval` у проверок здоровья | Ошибка на старых версиях Docker Engine |
| `name:` в стеке Portainer | Portainer задаёт имя проекта сам, был риск сломать стек |
| Профиль Compose для `cloudflared` в стеке Portainer | Сломал бы развёрнутый стек владельца |
| Поштучное сохранение снимка KMP, N+1 в запросах | Оставлено как есть при обзоре 31.10.2026; причина не записана |
| Очистка буфера `HttpContent` при выгрузке ключа из KMP | Только по возможности; в документах так и сказано |

## Пожелания владельца к панели

Из правок владельца; нарушать их не стоит.

- «Настройки — только настройки», горячих действий там нет. Кнопка — «Обновить», а не «Установить», и стоит не сверху у
  сервера, а в строке списка под состоянием.
- «Обзор» — состояние. Карточки серверов свёрнуты по умолчанию; фильтр — только плитки показателей, второй ряд кнопок отвергнут.
- Карточка сервера — один простой список: сертификат по умолчанию сверху и выделен, потом недостающие выбранные, потом остальные.
- Просроченная старая версия рядом с действующей новой — это не проблема: показывается одна строка, самая новая.
- Кнопка заблокирована — объясните почему: выключен, нет пароля, пароль отвергнут, нет прав.
- «Серверы» — связь, «Синхронизировать», «Подключить сервер», карандаш с настройками, удаление с кодом 2FA каждый раз.
- Интервал опроса — только в «Настройки → Синхронизация».

## Окружение Windows

- **`.gitignore`:** git на Windows не различает регистр, поэтому `secrets/` от корня (`/secrets/`) — иначе скрылись бы папки кода `Secrets/`.
- **LF в репозитории, CRLF в рабочей копии:** ошибки `dotnet format` про `ENDOFLINE` — артефакт; в CI шага форматирования нет.
- **Путь с пробелом** (`F:\Repos\kerio ssl updater`): `new URL().pathname` в Node ломается, нужен `fileURLToPath`.
- **Git Bash:** длинные heredoc падают с `unexpected EOF` и портят обратные косые — пишите скрипт в файл. Для `docker -v` нужен
  `MSYS_NO_PATHCONV=1`; `tar` принимает `C:/…` за удалённый хост — запускайте его из самой папки.
- **Python:** консоль cp1251, задавайте `PYTHONIOENCODING=utf-8`.
- **Тесты:** `dotnet test -nologo` возвращает код 5 (флаг не для MTP). `| tail` прячет код выхода: пишите лог в файл.
- **Типы панели:** `npx tsc --noEmit | tail` скрывает ошибки за сообщениями npm. Проверка — только `npm run build`.
- **Тестовый УЦ:** с постоянным именем цепочка в CryptoAPI ломалась после сотен запусков, поэтому имя случайное. Не возвращайте постоянное.
- **Сборка образа:** с `GenerateDocumentationFile=false` перестаёт работать IDE0005, поэтому `PublishDocumentationFile=false`.
- На машине не было `gh`; GitHub MCP закрытых репозиториев не видит, а обычный `git` с учётными данными видит.

## Нюансы развёртывания

- API не стартует на отставшей схеме. В Compose `migrate` — профиль `tools`, запускается руками; в Portainer сам, с кодом `exited (0)`.
- Стек Portainer передаёт секреты через `secrets: environment:`, а это несовместимо с `read_only` у той же службы.
- У API нет постоянного адреса в сети туннеля: иначе разовая `docker compose run api …` падает с `Address already in use`.
  Постоянный адрес — только у `cloudflared`, вне диапазона `KCM_TUNNEL_RANGE`; API верит `X-Forwarded-*` только от него.
- На той же машине работает соседний стек `eams-ssl-sender`. Поэтому порт публикации и подсеть туннеля здесь свои (`KCM_HTTP_PORT`, `KCM_TUNNEL_SUBNET`).
- Демо-ключ принимается только с `KCM_DEMO_MODE=true`.
- Несколько реплик API: `KCM_RUN_WORKER=true` оставьте только у одной. Первого администратора заводит только владелец.
- Свой УЦ у KMP: корень в контейнер и `SSL_CERT_FILE`. Настройки можно задать заранее: `Settings__<ключ>`.
- Новая основная версия PostgreSQL не открывает старые данные, Dependabot её не предлагает. Панель собирается только на LTS Node.
- `Kerio__AllowLoopback=true` разрешает адреса Kerio на этом компьютере — только тесты и разработка.

## Стенд и проверки

Запуск — в [CLAUDE.md](../CLAUDE.md), вход и адреса — в шапке `docker-compose.demo.yml`. Письма — в Mailpit, продление в
эмуляторе — `POST /emulator/kmp/renew?cn=…&days=…` (старые выпуски остаются).

- **Без `--no-deps` пересборка `api` пересоздаёт эмулятор:** он заново выпускает сертификаты, закреплённые отпечатки устаревают.
  Отпечаток меняется только через `PUT /api/kerio/servers/{id}/trust`, `PATCH` поля доверия игнорирует.
- **После `up -d` на образе `kerio-cert-manager:demo` убедитесь, что образ свежий:** после неудачной сборки стенд поднимется на старом.
- **Вход скриптом:** ответ входа несёт `details.challenge`, далее `POST /api/auth/two-factor`, опасные действия — `POST /api/me/step-up`.
- **Код TOTP одноразовый** в своём окне 30 с: дождитесь следующего, не запускайте два скрипта входа разом.
- **Первая настройка может упасть,** пока KMP не опрошен («не отдал ни одного сертификата»): просто повторите.
- **Настройки стенда:** `PATCH /api/settings/system` с `values`: `kerio.verify_seconds`, `keymanager.poll_minutes`,
  `kerio.alert_locale`, `kerio.dry_run`.
- **Скриншоты:** безголовый Chrome через CDP; встроенный браузер обрезает широкие страницы. Перед съёмкой `*-en.png` проверьте
  кириллицу во всех GET панели с `Accept-Language: en` (и `uk` на ы/э/ъ/ё).
- **Проверка выпуска:** проход и опрос при интервале 1 минута; закрытый порт в списке; очередь из нескольких имён и сводка;
  язык писем; метки на «Сертификаты»; журнал установок и письма в Mailpit.

Скрипты, которыми гонялся стенд (вход, наполнение, сценарии, скриншоты), в репозиторий не входят. Их копия — в
`.local/tools/demo-lab/`; проверяйте их на адреса, прежде чем переносить в git.

## Тестовый Kerio

Владелец разрешил опыты на своём тестовом сервере (адрес у владельца). Правила:

- Пароль вводит владелец в мастере подключения, не читайте поле и не ищите пароль в истории.
- Исходное состояние: встроенный `server` и основной сертификат домена (Let's Encrypt) по умолчанию. **Ключа к нему нет —
  удалять нельзя.** После опытов он должен снова быть сертификатом по умолчанию.
- Только одноразовые сертификаты. Стенд для проверки — опубликованный образ, эмулятор KMP, потом `down -v`.

Инцидент 30.10.2026. При первой пробе API тестовый сертификат был импортирован и удалён, и Kerio начал подавать встроенный
самоподписанный вместо основного, хотя список показывал прежний. К ночи 31.10.2026 порты снова подавали основной. Вывод
«импорт сразу активирует» опытами не подтвердился: метка в списке значила другое. Точную причину воспроизвести не удалось.
Итог для кода: верить только рукопожатию, не удалять то, что подаётся.

## Что не лежит в репозитории

Намеренно вне git; при переносе или переустановке сохраните отдельно:

| Что | Зачем |
|---|---|
| `secrets/` (прежде всего `kcm_master_kek`) | **Без мастер-ключа пароли Kerio, ключ KMP, пароль SMTP и коды 2FA из базы не открыть** |

| Тома Docker `kerio-cert-manager_*`, `certbridge_*` | Базы локальных установок. Живут на диске Docker, копия — `pg_dump` |

Локальная установка: `.env` подключает `.local/compose.lan.yml` через `COMPOSE_FILE`, панель — на `127.0.0.1:18001` и по HTTPS
в локальной сети с самоподписанным сертификатом. Обновление: новая версия в `KCM_IMAGE`, `docker compose pull api`,
`docker compose run --rm migrate`, `docker compose up -d`.

5. Вернуть файлы из таблицы выше. Модули уже в `modules/`; их репозитории нужны лишь для обновления копий.
